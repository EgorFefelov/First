# example/ — структура и соглашение

> Эталон «к чему идёшь» для блока 2. Зеркалит будущий `projects/site/` ученика.
> **Главный принцип: каждый проект — самодостаточная папка.** Всё, что проекту нужно
> (HTML, стили, скрипты, картинки, данные), лежит внутри его папки. Никаких общих слоёв
> и путей «наверх» (`../`) внутри проекта — только `./`. Так ученику просто: «вот папка
> моей игры — здесь вся игра».

## Зачем именно так

Это курс для детей 10–17. Сложная структура с общим `assets/` и путями `../../` —
лишняя когнитивная нагрузка. Самодостаточная папка = понятная ментальная модель:
один проект = одна папка = один продукт, который можно открыть, скопировать, задеплоить целиком.

Цена за простоту — **дублирование** (кадры комикса `scene_*.png` лежат и в `comics/`, и в `game/`;
базовые стили скопированы в каждый проект). Это сознательный размен: дубль картинок дешевле,
чем объяснять ребёнку общий слой и относительные пути.

## Структура

```
example/
├── index.html              ← точка входа: редирект на site/
│
├── site/                   ← ПРОЕКТ «визитка» (собирает остальные ссылками)
│   ├── index.html          (самодостаточна: CSS и JS инлайн внутри страницы)
│   └── *.png               (avatar — он же превью при шаринге, превью проектов)
│
├── comics/                 ← ПРОЕКТ «комикс»
│   ├── index.html
│   ├── style.css
│   ├── state.js comic.js   (рендер кадров из data/state.json)
│   ├── scenes/             (scene_1..6.png)
│   └── data/state.json
│
└── game/                   ← ПРОЕКТ «игра»
    ├── index.html
    ├── style.css
    ├── game.js
    ├── mechanics/          (mechanics.js + seek/fog/chase/collect/fridge)
    └── img/                (scene_1..6.png + magnet_*.png + bubble.png)
```

## Соглашение (зафиксировано)

1. **Проект = папка, всё своё внутри.** Пути внутри проекта — только относительные к самому проекту
   (`style.css`, `img/...`, `data/...`), без `../`.
2. **Единственное межпроектное звено — визитка.** `site/` ссылается на сёстры-папки
   `../comics/` и `../game/` (это честно: визитка «собирает» другие проекты). Других `../` в демо нет.
3. **Точка входа — корневой `index.html`** — лёгкий редирект на `site/`. Зашёл на адрес → визитка.
4. **Комикс** читает свой `data/state.json` (`window.STATE_BASE = "data/"` задаётся на странице
   ДО подключения `state.js`). Кадры — из `scenes/`.
5. **Игра** данные берёт из `CONFIG` в `game.js`; картинки — из `img/` (пути `img/...`).
6. **Дубли допустимы и ожидаемы.** `scene_*.png` есть и в `comics/scenes/`, и в `game/img/` —
   у каждого проекта свой набор. Базовые стили скопированы в `style.css` каждого проекта.

## Что НЕ кладётся сюда (остаётся в reference-demo/ как кухня)

- `demo.html` — SPA-эталон/исходник.
- `process/` — промежуточные итерации картинок; `crop_frames.py` и скрипты-инструменты.
- `*_raw.png` магниты — сырьё.
- `gallery.json`, `board.js` — галерея процесса: в демо нет потребителя.
- `bubble.js` — рендер живого Бабла из state; в каркасе Бабл на визитке = инлайн-эмодзи, файл не нужен.
- `hero.js` / `scene.js` — заглушки с console.log.
