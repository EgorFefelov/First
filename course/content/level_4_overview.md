# Уровень 4 — публикация: сайт в интернет (overview для наставника)

> **Читай первым при входе в Уровень 4** (когда `current_step` стал `"4.0"`). Здесь специфика уровня: роль ребёнка, граница (публикует взрослый), запись в state. Шаговые методички — `level_4_<N>.md`. Общие правила роли — в `.claude/CLAUDE.md`.

Уровень 3 закончился сайтом, который работает локально (двойной клик). Уровень 4 выкладывает этот сайт **в интернет**: продукт ребёнка получает свой адрес `teens.make-it.kz/<ник>` и выходит к реальным людям. Это финал блока 2 и текущего курса. Шаги: **4.0 → 4.1 → 4.2 → 4.3 → 4.4 → 4.5**, методички — `course/content/level_4_<N>.md`. Последний шаг — **4.5 «Покажи миру»** (ребёнок делится ссылкой); там лвл-ап.

**Карта шагов:**

- **4.0** — ввод в уровень (разговор-настройка).
- **4.1** — проверка готовности сайта (релизный чеклист, локально).
- **4.2** — **сборка точки входа (НОВЫЙ): ребёнок собирает страницу-вход `projects/index.html` (редирект на `site/`) + «бирку для шаринга» (OG = аватар) на входе и в визитке. Делает сам, с Баблом, как секции Уровня 3.**
- **4.3** — публикация (выкладывает взрослый, ребёнок получает адрес и открывает его).
- **4.4** — прод-тест (проход по боевому адресу, цикл правок).
- **4.5** — шаринг + лвл-ап (ребёнок делится ссылкой).

**Предусловие входа:** сайт собран и работает локально — `checkpoints["L3.done"]==true`. Если нет — Уровень 4 не начинаешь, возвращаешься достроить сайт (публиковать нечего).

## Роль ребёнка и граница (важно — публикует взрослый)

Ребёнок **не деплоит сам и не видит технику** (сервер, SSH, домены, скрипты — ничего этого в чате нет). Его роль: **проверяет готовность (4.1) → собирает обложку-вход сам, с Баблом (4.2) → ждёт, пока выложит взрослый (4.3) → получает ссылку и открывает её → проверяет вживую на проде (4.4) → шарит (4.5)**. Сборку точки входа (4.2) ребёнок делает сам, как секции Уровня 3 (это не техника наставника); заливку на сервер делает взрослый — скрипт `deploy-student.sh` тот же.

- **Сам деплой делает взрослый/учитель** — запускает готовый скрипт `deploy-student.sh <папка-projects-ученика> <ник>`. **Ты (наставник) деплой НЕ запускаешь** — в курсе нет доступа к серверу. Ты оформляешь момент публикации и выдаёшь ссылку, когда взрослый выложил.
- Слова «сервер», «SSH», «nginx», «домен», «деплой», «скрипт» в чате с ребёнком **не используешь**. Для него есть «выложим в интернет» и «твой адрес».

## Как берётся ник (адрес сайта) — твоя кухня, ребёнку не объясняешь

Адрес — `teens.make-it.kz/<ник>`. Ник:

- **Основной путь:** owner из `git remote get-url origin` (`github.com/<ник>/make-iteens-course` → `<ник>`). Работает, если форк выдан под аккаунтом ученика. Username GitHub уникален → адреса не сталкиваются.
- **Фолбэк:** если `origin` отсутствует или указывает на апстрим (не на репо ученика) — ник из `state.site.published.nick`, заданного заранее при настройке форка. Конвенция: латиница, lowercase, без пробелов.
- В обоих случаях — проверка против списка зарезервированных имён в `deploy-student.sh` (`assets`, `demo`, `index`, `api`, `students`, `404`).
- На 2026-06-19 рабочий путь — фолбэк через state (механика выдачи форка под аккаунтом ученика дорабатывается).

## Цикл правок на проде (4.4) — правка НЕ блокирует

На прод-тесте (4.4) могут вылезти проблемы, которых не было локально (чаще всего — разъехавшиеся ссылки между проектами; реже — комикс не грузит сцены по http, тяжёлые картинки). Цикл: ребёнок нашёл → **ты правишь** (по границе Уровня 3) → **взрослый выкладывает заново** (повторный `deploy-student.sh`, скрипт идемпотентен) → проверяем снова.

- **Правка не блокирует прохождение.** Если взрослый занят другими учениками — закрываешь `4.4.fix` с пометкой «правка в очереди на повторную публикацию» и ведёшь ребёнка к 4.5. Не сажаешь ребёнка ждать.
- Если на проде всё чисто с первого раза — `4.4.fix` закрывается без правок, искусственный цикл не делаешь.

## Шаринг и превью (4.5)

Ребёнок делится ссылкой сам (его выбор, кому; достаточно одного человека). Превью (карточка с аватаром при отправке ссылки) показываешь мягко — «смотри, красиво разворачивается», без техники. **NB:** первый шаринг — после того как убедился, что превью правильное: Telegram кеширует превью, и если кинуть раньше времени, оно может быть старым/пустым (в моменте кеш не сбросить).

## Что тебе МОЖНО / НЕЛЬЗЯ на Уровне 4

- **МОЖНО:** правки внутри `projects/` ученика по границе Уровня 3 (тексты, ссылки, картинки) — для фиксов по итогам прод-теста.
- **НЕЛЬЗЯ:** запускать деплой (нет доступа к серверу — это делает взрослый), трогать инфру публикации (`deploy-student.sh`, серверный конфиг — не в этом репо), а также всё из общих технических запретов.

## Запись в state на Уровне 4

Тот же ритм — одна правка в конце шага. Блок **`site.published`** в `state.json`:

- Блок `site.published` (`nick`/`url` пустые, `deployed`/`prod_checked`/`shared` = `false`) уже есть в `state.json` форка — на **4.0** ничего заводить не нужно.
- **4.2 (сборка)** — `checkpoints["4.2.done"]=true`. Нового поля в `site.published` не добавляем (структура `projects/` — код, не данные прогресса).
- `nick`/`url`/`deployed=true` — на **4.3** (после того как взрослый выложил).
- `prod_checked=true` — на **4.4**.
- `shared=true` — на **4.5**.
- Лвл-ап на 4.5: `checkpoints["4.5.done"]=true` и `checkpoints["L4.done"]=true`, `current_step` остаётся `"4.5"` (следующего шага в `content/` нет — финал блока).
