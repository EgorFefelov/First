# Шаг 4.3 — Публикуем

> Цель шага: сайт ребёнка выходит в интернет и получает свой адрес `teens.make-it.kz/<ник>`. Технически выкладывает взрослый/учитель — ребёнок не видит сервер и не настраивает ничего. Для ребёнка это момент «мой сайт теперь в интернете, у него есть адрес», и он открывает свою ссылку.
> Этот шаг — ключевой: продукт выходит в реальный мир. Деплой делает взрослый, ребёнок получает ссылку и открывает её.

## Чеклист шага

- **4.3.published** — сайт ребёнка выложен в интернет, доступен по адресу `teens.make-it.kz/<ник>`
- **4.3.link** — ребёнок получил свою ссылку и открыл её: сайт грузится из интернета

> `4.3.published` — это факт публикации (делает взрослый). `4.3.link` закрывается, когда ребёнок сам открыл свой адрес и увидел, что сайт загрузился.

---

# Твой сайт теперь в интернете

Главный смысл шага для ребёнка — **момент**, а не техническая операция. Оформи это как событие: сайт ребёнка выходит в интернет и получает свой собственный адрес.

> Готово — твой сайт теперь в интернете! Вот твой адрес: `teens.make-it.kz/<ник>`. Открой его.

Когда сайт выложен и доступен по адресу — пункт `4.3.published` закрыт.

---

# Это уже не папка у тебя — это настоящий адрес

Когда ребёнок открывает свою ссылку, важно поймать разницу: сайт открылся **с сервера, из интернета**, а не двойным кликом с его компьютера.

> Смотри — это открылось не с твоего компьютера, а из интернета. По этому адресу твой сайт откроется у кого угодно, на любом телефоне.

Прод-тест (пройти по сайту и убедиться, что всё работает на боевом адресе) — следующий шаг 4.4. Здесь — сам факт «опубликовано, вот твоя ссылка, ты её открыл».

Когда ребёнок открыл свой адрес и сайт загрузился — пункт `4.3.link` закрыт.

## Для наставника: кто и как выкладывает (важно — фаза 1)

- **Сам деплой делает взрослый/учитель**, не ты (Бабл/наставник) и не ребёнок. Под капотом это запуск готового скрипта `deploy-student.sh <папка-projects-ученика> <ник>`. **Ты деплой НЕ запускаешь** — в курсе нет доступа к серверу. Ты оформляешь момент и выдаёшь ссылку, когда взрослый выложил.
- Ребёнок про сервер/SSH/nginx/скрипты **не знает**. Он видит только результат — свою ссылку.
- Если сайт ещё не выложен (взрослый не успел) — не выдавай ссылку и не говори «опубликовано». Дождись факта публикации, потом оформляй момент.

## Для наставника: как берётся ник (адрес сайта)

Адрес — `teens.make-it.kz/<ник>`. Ник берётся одним из двух путей:

- **Основной:** ник = владелец гит-репозитория ученика — owner из `git remote get-url origin` (`github.com/<ник>/make-iteens-course` → `<ник>`). Имя пользователя на GitHub уникально, поэтому два ученика не получат один адрес. Работает, **если форк выдан под аккаунтом самого ученика**.
- **Фолбэк:** если `origin` отсутствует или указывает на апстрим (не на репо ученика) — ник берётся из `state.site.published.nick`, заданного заранее при настройке форка. Конвенция ника: латиница, маленькие буквы, без пробелов (это сегмент адреса).
- В обоих случаях ник проверяется против списка зарезервированных имён (зашит в `deploy-student.sh`: `assets`, `demo`, `index`, `api`, `students`, `404`) — чтобы адрес сайта не совпал со служебным.

> На 2026-06-19: `origin` форка пока указывает на апстрим, механика выдачи форка под аккаунтом ученика дорабатывается. До этого рабочий путь — фолбэк через `state.site.published.nick`. Эти детали — твоя кухня, ребёнку про ник из репозитория ничего не объясняешь, он просто получает готовый адрес.

## Для наставника: что записать

Запись при закрытии шага (корневой `state.json`, после того как взрослый выложил сайт):

- Пункты чеклиста 4.3 → `done` с короткими `note`.
- `state.site.published.nick` = ник; `state.site.published.url` = `https://teens.make-it.kz/<ник>`; `state.site.published.deployed` = `true`.
- `checkpoints["4.3.done"] = true`, `current_step` → `"4.4"`.
