# Механики игры — переиспользуемые тулы

Каждая механика — отдельный файл `<name>.js` в этой папке. Это «трение» на
кадре: что герой должен сделать, чтобы добыть награду и открыть переход дальше.

Движок (`core.js`) **не знает** про конкретные механики. Он работает с любой
через единый контракт. Поэтому механики:
- переиспользуемы — ученик/агент берёт готовую, не пишет с нуля;
- взаимозаменяемы — можно чередовать или раздавать кадрам случайно.

## Контракт механики

Каждый файл регистрирует механику через `Mechanics.register(name, factory)`.
`factory()` возвращает объект с методами:

```js
Mechanics.register("seek", () => ({
  // вызывается при входе на кадр. ctx — 2d-контекст, cfg — CONFIG, scene — её данные из SCENES
  init(ctx, cfg, scene) { ... },

  // каждый кадр игры. bubble — { x, y, vx, vy }, keys — нажатые клавиши
  update(bubble, keys) { ... },

  // своя отрисовка поверх фона (награда, подсказки, эффекты)
  draw(ctx) { ... },

  // true -> кадр пройден, награда добыта, переход E разблокирован
  isComplete() { ... },

  // сброс при повторном входе на кадр (рестарт / возврат)
  reset() { ... },
}));
```

Опциональные методы (есть в готовых механиках; без них своя механика
не получит подбор награды по клавише E):

```js
  // реакция на клавишу E. Вернуть true, если событие «съедено»
  // (например, награда подобрана) — тогда переход на E не сработает
  onAction(bubble) { ... },

  // true -> герой достаточно близко, чтобы подобрать награду
  // (движок показывает подсказку «E — взять»)
  canPickup(bubble) { ... },
```

## Как подключить механику к кадру

В `CONFIG.SCENES` у кадра указывается имя механики:

```js
{ image: "comic/scene_2.png", mechanic: "seek" }
```

Кадр без поля `mechanic` — без «трения», переход открыт сразу (старт/финал).

## Реестр

`mechanics.js` — реестр (`Mechanics.register` / `Mechanics.create`).
Подключать в HTML ДО `core.js`, после — файлы механик:

```html
<script src="assets/mechanics/mechanics.js"></script>
<script src="assets/mechanics/seek.js"></script>
<script src="assets/mechanics/fog.js"></script>
<script src="assets/mechanics/chase.js"></script>
<script src="assets/mechanics/collect.js"></script>
<!-- ... другие механики ... -->
<script src="assets/core.js"></script>
```

## Готовые механики

- `seek.js` — «Искатель»: на кадре спрятана награда, герой находит касанием.
  Позиция награды — `scene.seek = { x, y }` (доли 0..1).
- `fog.js` — «Проявитель»: кадр затянут туманом, герой рассеивает его движением;
  рассеял ~порог — появляется награда, ловится касанием.
  Позиция награды — `scene.fog = { x, y }` (доли 0..1).
- `chase.js` — «Догонялки»: награда дрейфует и убегает от героя, надо догнать.
  Старт награды — `scene.chase = { x, y }` (доли 0..1).
- `collect.js` — «Собиратель»: награда разбита на кусочки, собрать все.
  Раскладка кусочков — `scene.collect = [{ x, y }, ...]` (доли 0..1),
  позиция собранной награды — `scene.collectFinal = { x, y }`.
- `arrange.js` — «Финальная полка»: расставить собранные награды в области кадра
  (полка / витрина / постамент / гнездо — по истории ученика).
  Прямоугольник области — `scene.arrange = { x, y, w, h }` (доли 0..1).

## Пример «своей механики»

`dodge_collect.js` — не базовая механика, а **образец** того, как ученик пишет
СВОЁ испытание по контракту реестра (методичка 2.4). Леталка: по полю плывут
«цели» (лови касанием, +1) и «помехи» (заденешь — −1); набрал `CONFIG.dodgeGoal`
— переход открыт. Спрайт цели — `scene.reward`; спрайт помехи (необязательно) —
`scene.hazardSprite`, иначе рисуется примитив. Параметры темпа — `dodge*` в
`config.js`. На старте не подключён; наставник дописывает `<script>` в
`index.html`, когда ученик делает своё испытание. Читать как пример структуры,
а не как готовый набор — тему («что за цель и помеха») ученик придумывает сам.
