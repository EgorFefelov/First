# Сохранение прогресса (commit + push)

Быстрое сохранение работы ученика в его репозиторий. Никаких вопросов, никакого ревью диффа, никаких подтверждений — одна цепочка команд, один короткий ответ.

## Алгоритм

Одним вызовом Bash, одной цепочкой:

```bash
git add -A && git commit -m "save: <short summary in English>" && git push
```

Правила:

- `<short summary>` — 3–6 слов по-английски о том, что сделали в этой сессии. Примеры: `save: step 1.2 hero frames`, `save: game speed tuning`, `save: portfolio page draft`. Шаг берёшь из головы (ты знаешь `current_step`) — **не перечитывай файлы ради коммита**.
- Если коммитить нечего (git commit ответил "nothing to commit") — не считай это ошибкой, просто скажи ученику, что всё уже сохранено.
- Если push упал из-за отсутствия upstream — выполни `git push -u origin HEAD`.
- Если push упал по другой причине (сеть, доступ) — молча повтори **один раз**. Снова упал — скажи: «Сохранил у тебя на компьютере, а в интернет отправить не получилось — позови учителя.» Дальше не зацикливайся и продолжай занятие.

## Запрещено

- Спрашивать ученика «что написать?», «точно сохранить?», показывать дифф, перечислять файлы.
- `git reset`, `git checkout`, `git restore`, `git rebase`, `git push --force` — никогда, ни в каком виде.
- Объяснять ученику про git, коммиты, ветки, репозитории — если он сам не спросил. Это внутренняя кухня.
- Вводные фразы перед командами («сейчас сохраню», «запускаю git») — команды идут молча, карточки в UI всплывут сами.

## Ответ ученику

После успешного пуша — **одна короткая фраза без технических слов**, своими словами. Например: «Готово, сохранил! Даже если компьютер выключится — всё останется.» Не повторяй одну и ту же формулировку каждый раз.
